Overview

Two levels of loading state: a local indicator on the element that is waiting (a button, a card, a form) and a global bar at the top of the viewport that the shell renders by itself.

Local

Add [kitBusy] (import KitBusy) to any element. A button swaps its label for a spinner at the same width and swallows clicks while staying focusable. Anything else is covered by a scrim and spinner and made inert. .kit-spinner and .kit-skeleton are plain classes for the rest.

Orders

Some content that is about to be refreshed.


Global

KitLoadingService counts overlapping operations behind the bar at the top edge of the viewport. The bar appears only after an operation has lasted 150 ms and stays for at least 400 ms, so quick requests never flash it. Tune that with KIT_LOADING_OPTIONS.

Nothing is tracked automatically unless you opt in: kitLoadingInterceptor for HTTP requests (skip one with KIT_LOADING_SKIP) and provideKitNavigationLoading() for router navigations.

Try it

Styles

The classes ship in their own stylesheet and are also part of primitives. The bar itself is part of the shell stylesheet.

API

Name Description
KitBusy The [kitBusy] directive, local busy state for a button or any other element
KitLoadingService begin(), track(promise | observable) and the isLoading signal behind the global bar
KIT_LOADING_OPTIONS Injection token for the bar's show delay and minimum visible time
kitLoadingInterceptor Opt-in HTTP interceptor reporting requests to the service
KIT_LOADING_SKIP HTTP context flag keeping a request out of the global state, built with kitLoadingSkipContext()
provideKitNavigationLoading() Opt-in provider reporting router navigations to the service
