Overview

Every native form control, shown as it renders in the dark and light scheme, the kit classes on each. What the kit leaves to the browser is noted where it comes up: the datalist popup, the image input and the output element, which have nothing of their own to style.

Headings marked kit are the controls that carry kit classes.

Setup

All of it ships in primitives, after the design tokens. Each control also has a module of its own to take on its own.

Text inputs kit

A kit-field wraps a label and its control, the label's for matching the control's id. The same markup serves every text-like type, the date and time ones below, and the states, which are the native attributes. An invalid value is marked with aria-invalid and explained under the field with kit-field__error. With Signal Forms, <kit-field-error> renders that line from the field's first error (see Forms).

@for (type of textTypes; track type) {
}

States

Invalid

An invalid field gets a 2px danger border, and a message under it: an icon and the text, never only a color. Mark it with aria-invalid="true" and point aria-describedby at the message. The browser's own validation shows the same look once the person has interacted with the field (:user-invalid, not :invalid, which would flag an untouched required field). A focused invalid field keeps the danger border and rings it in danger too, the pink ring would be too close to it.

Multi-line, choice and files kit

textarea, select, file and color take the same kit-field__control as a text input, and adapt to the element: a textarea grows with its rows, a select gets the kit's chevron, a file input its styled button.

Optional color kit

A native color input can't be empty, it shows black. <kit-color-field> tells "black" from "not set": the swatch with the hex value, or the "not set" text, and with clearable a button that unsets it. The value is null when unset. It is a Signal Forms control, [formField] binds a string | null field.

Chips and chip input kit

<kit-chip-input> is a list of short texts: type one, press Enter or a comma, get a removable chip. Paste a list and it is split, Backspace in an empty field removes the last chip. It only trims and drops empty texts: the duplicates and the limits are validators of the field, <kit-field-error> shows them under the chips (try a fourth chip below, or the same text twice). A Signal Forms control, or [(value)]. The chips themselves are kit-chip in a kit-chips list, primary ink on the sunken surface.
